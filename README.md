# VK-бот: приветствия + AI-ответы (VKBottle + ProxyAPI)

Бот для сообщества ВКонтакте, который:

- **приветствует новых пользователей** — участников, добавленных в беседу, и первого собеседника в личных сообщениях;
- **отвечает на входящие сообщения при помощи AI** — через провайдер [ProxyAPI](https://proxyapi.ru/docs/openai-text-generation) и модель `gpt-4.1-mini`.

Работает на **Long Poll API** (свой сервер не нужен), ключи хранятся в `.env` и читаются через `python-dotenv`.

Локальная документация по VKBottle, на которой построен проект: [`docs/`](docs/README.md).

## Настройка

### 1. Токен сообщества

ВКонтакте → **Управление сообществом → Работа с API → Ключи доступа** → создать ключ с правами `messages`, `groups`, `users`.

### 2. Ключ ProxyAPI

[Личный кабинет ProxyAPI](https://proxyapi.ru) → создать API-ключ, пополнить баланс.

### 3. Заполнить `.env`

```console
copy .env.example .env
```

| Переменная | Назначение |
|---|---|
| `VK_TOKEN` | ключ доступа сообщества |
| `PROXYAPI_API_KEY` | ключ ProxyAPI |
| `PROXYAPI_BASE_URL` | базовый адрес API (по умолчанию `https://api.proxyapi.ru/v1`) |
| `AI_MODEL` | идентификатор модели (см. ниже) |
| `AI_SYSTEM_PROMPT` | системный промпт помощника |
| `AI_HISTORY_LIMIT` | сколько последних реплик помнит диалог |
| `LONGPOLL_WAIT` | секунды ожидания ответа LongPoll |
| `LONGPOLL_RPS_DELAY` | задержка между запросами LongPoll, сек |
| `LOG_LEVEL` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |

### 4. Настройки сообщества

- **Работа с API** → включить **Long Poll API** (стабильная версия — `5.131`);
- **Сообщения** → разрешить сообщения сообществу, включить обработку входящих событий.

Без этих галочек бот запустится, но сообщения получать не будет.

Оба варианта рабочие — `bot.py` сам подставляет корень проекта в `sys.path`:

```console
python src\bot.py
```

```console
python -m src.bot
```

Ожидаемый вывод:

```
Бот запускается (LongPoll, wait=25 c), AI-модель: openai/gpt-4.1-mini
```

Остановить — `Ctrl+C`.

## Как бот обрабатывает события

Хендлеры проверяются **в порядке подключения** (см. `src/handlers/__init__.py`), первый сработавший выигрывает.

| # | Хендлер | Правила | Что делает |
|---|---|---|---|
| 1 | `greet_chat_member` | `PeerRule` + `ChatActionRule` | приветствие участника, добавленного в беседу |
| 2 | `private_message` | `PeerRule(private)` + есть текст | первое сообщение → приветствие, дальше → AI |
| 3 | `chat_mention` | `PeerRule(chat)` + `MentionRule` + есть текст | ответ на `@упоминание` |
| 4 | `chat_reply` | `PeerRule(chat)` + `ReplyToBotRule` + есть текст | ответ на цитату сообщения бота |

В беседе бот **не отвечает на всё подряд** — только на упоминание или ответ на своё сообщение, иначе он мусорил бы в общем чате.

### Два важных нюанса реализации

1. **`replace_mention`**. У `MessageView` в VKBottle по умолчанию `replace_mention = False`: упоминание не вырезается из текста, а `is_mentioned` всегда `False` — то есть `MentionRule` вообще не срабатывает. В `src/bot.py` это включается явно, заодно `@бот` вырезается из текста до того, как он попадёт в модель.

2. **Приветствие занимает первое сообщение**. Хендлеры блокирующие, поэтому приветствие отправляется вместо ответа модели — ровно один раз на диалог. Все следующие сообщения уходят в AI.

### Память диалогов

`src/ai.py` хранит историю по `peer_id` в `deque(maxlen=AI_HISTORY_LIMIT)`. История **живёт только пока работает процесс** — после перезапуска диалог начинается заново. То же касается списка уже поздорованных собеседников.

## Проверка подключения к ProxyAPI

Проверить адрес, ключ и модель можно одной командой (замените ключ на свой):

```console
curl https://api.proxyapi.ru/v1/chat/completions -H "Content-Type: application/json" -H "Authorization: Bearer ВАШ_КЛЮЧ" -d "{\"model\":\"openai/gpt-4.1-mini\",\"messages\":[{\"role\":\"user\",\"content\":\"привет\"}]}"
```

### Идентификатор модели

По [документации ProxyAPI](https://proxyapi.ru/docs) идентификатор модели состоит из вендора и названия через слэш (`openai/gpt-4.1-mini`, `anthropic/claude-...`), регистр не важен. Поэтому в `.env` записано:

```
AI_MODEL=openai/gpt-4.1-mini
```

Это и есть **gpt-4.1-mini**. Если ответ придёт с ошибкой `model not found` — попробуйте записать без префикса:

```
AI_MODEL=gpt-4.1-mini
```

### Типовые ошибки

| Симптом | Причина |
|---|---|
| `Не смог получить ответ от нейросети...` в чате | ProxyAPI недоступен / ошибка модели — подробности в логах (`LOG_LEVEL=DEBUG`) |
| `401` | неверный `PROXYAPI_API_KEY` |
| `402` | не пополнен баланс |
| `model not found` | см. про `AI_MODEL` выше |
| Бот молчит в беседе | нет `@упоминания` и нет ответа на его сообщение — это ожидаемо |
| Бот молчит вообще | не включён Long Poll API в настройках сообщества |
